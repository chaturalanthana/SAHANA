# Requirements Traceability Matrix

Status: milestone code through Milestone 6 is in the repository as of 31 October 2026. Automated API tests cover society isolation, configuration, member lifecycle, welfare eligibility, ledger posting and reversal, projects, emergency submission, and ESG counting. Rows stay **In progress** where the screen or report is only partial. **Blocked** remains where a production capacity or migration claim was not executed. Sinhala and Tamil catalogs are unreviewed drafts (OD 06). GitHub Actions evidence is the pull request workflow, not this note.
Sources:

- SRS: SAHANA Initial SRS v1.0, 31 October 2026. Clauses SRS 001–SRS 034. Open decisions OD 01–OD 08.
- Prompt: master build prompt sections 6.1–6.17. Where the prompt is stricter than the SRS and does not contradict it, the prompt is recorded as confirmed scope (see CD-07, CD-12 in `docs/decisions/DECISIONS.md`).
- Context only: SAHANA Requirements — October 2026 proposal deck for the CBL Employee Welfare Society. It does not add formulas.

Status values:

- **Planned** — in an MVP milestone; not blocked by a missing formula.
- **In progress** — Milestone 0 code exists and local tests have run. Not Done until the Definition of Done is met.
- **Blocked** — do not implement the named behavior until the decision is accepted.
- **Deferred** — Phase 2, out of MVP (NN-01).

Updating this file is part of the Definition of Done. Do not mark a row **Done** until that definition is met and tests were executed.

## Traceability gaps found while writing this matrix

Recorded here so they are not rediscovered as surprises in code:

1. Required member fields, category list, and lifecycle status list are not specified (OD 01).
2. No welfare policy document or sample eligible, ineligible, and exception cases was attached (OD 02). The SRS review focus asks for them before rule configuration.
3. No chart of accounts was attached (OD 03).
4. Acknowledgement time, escalation contacts, and location retention for emergencies are explicitly "must be agreed" (SRS 016, OD 04).
5. Fallback language is required by SRS 004 and not chosen (OD 06).
6. Performance numbers are required before a capacity claim and are not chosen (OD 07, SRS 033).
7. The repository had no existing implementation on 31 October 2026. There is no legacy code to preserve or to reconcile.
